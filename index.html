Flux

Distributed notification system

API→BullMQ→Workers→Providers↘DLQ + replay
  • Fault-tolerant delivery against provider failures: backoff retries, a Dead Letter Queue and a replay endpoint for failed notifications.
  • Idempotent workers using Redis locks, atomic status claims and a per-channel circuit breaker.

Ride Matching Engine

Real-time ride dispatch

Rider request→Redis GEO→Atomic reserve→WebSocket offer→Accept / fallback
  • Finds nearby drivers with Redis GEO queries and reserves them atomically, falling back to the next driver on reject or timeout.
  • Prevents double-booking with Redis optimistic locking (WATCH/MULTI/EXEC) and duplicate dispatch with a token-guarded per-ride lock (SET NX + TTL). Verified with custom concurrency tests.
  • WebSocket offer/accept flow with timeouts and a live React dashboard fed by an event bus.

Node.js, Redis, WebSockets, React
